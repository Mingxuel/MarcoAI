# journals/ — 复盘日志体系

> 维护者：小志（日志管理大师）　｜　日志作者：用户　｜　下游：小小A（超短线教练）
> 一句话：用户写日志 → 小志做结构化总结/索引/标签 → 摘要交给小小A。

## 1. 目录结构

```text
journals/
├─ README.md                 本文件：规范与流程
├─ TEMPLATE.md               日志模板（复制 → YYYY-MM-DD.md）
├─ YYYY-MM-DD.md             用户写的当日日志（一天一篇，UTF-8 Markdown）
├─ INDEX.md                  索引：日期 + 一句话 + 标签（小志维护）
├─ TAGS.md                   风格标签统计（小志维护）
├─ SUMMARY_SCHEMA.md         每日摘要固定格式：小小A 评分要的字段清单
├─ .summary-state.json       增量处理状态（小志维护，勿手改）
├─ summaries/
│  ├─ YYYY-MM-DD.md          当日结构化总结（小志维护，按 SUMMARY_SCHEMA.md）
│  ├─ legacy-notes.md        旧笔记迁移摘要（来源 AIData/DAILY/Daily.txt）
│  └─ 2026-11-04-sample.md   示例总结（演示格式，不计入统计）
├─ samples/
│  └─ 2026-11-04-sample.md   示例日志（演示写法，不被每日扫描）
└─ coach/                    小小A 的教练知识库（PLAYBOOK / USER_PROFILE / RUBRIC / REVIEW）
                             ★ 只由小小A 维护，小志不写
```

## 2. 怎么写（用户只看这一节就够）

1. 复制 `TEMPLATE.md` → 改名 `journals/YYYY-MM-DD.md`（如 `journals/2026-11-05.md`）。
2. 编码 UTF-8、Markdown；有就写，没有写「无」，**不编数字**。
3. 六个必填栏目：**市场/情绪、今日操作、盈亏、犯错/冲动、明日计划、一句话复盘**。
4. 每笔尽量写全「买卖价 / 仓位% / 止损价 / 盈亏%」，**代码必填**（6 位 + `.SH/.SZ`，没记写「无代码（不可对账）」）；环境四件套（指数/两市成交/涨停家数/连板高度）与当日候选数有就写；当天新旧卖法混用时每笔标「卖法=B+/旧」——这些是小小A 评纪律/仓位/环境与归因的硬需求，缺了她会标「无」，不影响你写。
5. 当天补改：直接编辑原文件即可，小志按修改时间识别「更新」，会重做该日总结。
6. 想少写：至少留「市场/情绪」「今日操作」「一句话复盘」三节，其余写「无」。

## 3. 边界（重要）

- 日志 = 用户原始记录，**小志不改原文、不删不改**。
- summary = 事实提取 + 标签 + 原文摘录，**不评价、不指导、不预测**。
- 教练建议、用户画像、评分、复盘对话只在 `journals/coach/`，由**小小A**写。
- 日志属私有内容：**不外传**，不进汇报正文；只把摘要发小小A 与 Lead。

## 4. 每日流程（小志执行）

1. 只扫 `journals/*.md`（跳过 `README.md` / `TEMPLATE.md` / `INDEX.md` / `TAGS.md` / `SUMMARY_SCHEMA.md`；`summaries/`、`samples/` 不扫）。
2. 用 `.summary-state.json` 里记录的 mtime 判断「新增 / 更新」，**不重扫已处理文件**；无记录且 mtime 更晚的才处理。
3. 为每篇新日志写 `summaries/<日期>.md`，严格按 [SUMMARY_SCHEMA.md](SUMMARY_SCHEMA.md) 的 9 段格式。
4. 更新 `INDEX.md`（日期 + 一句话 + 标签 + summary 链接）与 `TAGS.md`（计数、错误归类标签）。
5. `send_message` 给 `xiao-xiao-a`：≤15 行摘要（关键数 + 一句原文 + 交接项）+ 新日志与 summary 路径。
6. 给 Lead 发 ≤5 行「本次新增/更新路径 + 一句话」。
7. 无新日志 → 只回「今日暂无新日志」并提醒可用 `TEMPLATE.md`，**不催促**。

## 5. 总结 schema（固定 9 段，顺序不变）

完整字段与填写规则见 [SUMMARY_SCHEMA.md](SUMMARY_SCHEMA.md)：

1. 日期（交易日/非交易日、补写/更新）
2. 环境四件套 + 当日候选数 + 市场情绪 / 主线
3. 操作清单（逐笔：代码 / 方向 / 买卖价 / 仓位% / 止损价 / 盈亏% / 计划内? / 理由原话）
4. 盈亏
5. 纪律与错误（按计划止损 是/否、仓位超限、计划外单、错误归类标签）
6. 风格标签
7. 值得回看的一句（原文逐字摘录）
8. 交接区（定义类开放问题、边界单做没做——只给小小A，小志不下结论）
9. 数据来源与缺口

## 6. 标签口径

- **用户指定标签**：打板、低吸、半路、接力、追高、止损、仓位、情绪。
- **错误归类标签**（小小A 评分用）：追高、硬开仓、未止损、仓位超限、风格漂移、无。
- **扩展标签**（按需新增，先在 `TAGS.md` 登记）：均线（MA5/20/60）、影线、量能、优先级/选股、降预期、高开走、隔日超短、计划外、加仓/补票。
- **计数口径**：新日志 = 每篇每标签计 1 次；旧笔记基线 = 原文关键词粗匹配出现次数（`TAGS.md` 分两列展示，不混算）。

## 7. FAQ

| 问题 | 答案 |
|---|---|
| 今天没写日志？ | 小志不会催；被唤醒只会回「今日暂无新日志」。 |
| 昨天忘了写？ | 直接补 `journals/YYYY-MM-DD.md`，下次唤醒一起总结。 |
| 只想写几句？ | 见 §2 第 6 条的最小格式。 |
| 总结为什么这么细？ | 小小A 要评「纪律/仓位/复盘」三维，缺买卖价、仓位%、止损价、盈亏% 就无法评分；缺了就写「无」，不硬凑。 |
| 旧笔记去哪了？ | 摘要见 `summaries/legacy-notes.md`；原文仍在 `AIData/DAILY/Daily.txt`，**未改动**。 |
| 能改总结吗？ | 可以改 `summaries/` 里的文字；`INDEX.md`/`TAGS.md` 由小志统一维护，改了会与统计打架，要改请说一声。 |
| 示例文件要留着吗？ | 不需要时删 `samples/` 与 `summaries/2026-11-04-sample.md`，并去掉 INDEX 里对应一行。 |

## 8. 与仓库其他文档的关系

- 放置规则：根目录 `FILE_ROUTING.md`（`journals/` 只放文本；不进更新菜单；`journals/coach/` 只由小小A 维护）。
- 目录职责：根目录 `ARCHITECTURE.md`。
- 日志、总结均为文本，随仓库入库；代码/数据/生成物不放这里。
