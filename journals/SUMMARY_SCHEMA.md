# 每日摘要 schema（小志 → 小小A 的固定格式）

> 维护者：小志　｜　依据：小小A 2026-11-04 提出的评分需求　｜　每篇 `journals/summaries/YYYY-MM-DD.md` 按本文件写
> 原则：**有就写、没有写「无」、不编数字、不评价、不预测**；缺失项直接标「无」，不要为凑数去算。

## 顺序（不可调换）

### 1. 日期

`YYYY-MM-DD`（星期几；交易日 / 非交易日；是否补写或更新）

### 2. 环境四件套 + 市场情绪 / 主线

- 指数：沪指 ____% / 创业板 ____%
- 两市成交：____ 亿
- 涨停家数：____ 家；连板高度：____ 板
- **当日候选数**：____（如 TPO_M5 行数；用户没写就「无」）
- **B+ 环境判定（选填）**：7 宽基中在日线 MA60 上方 __/7 → 宽 / 差；数据源 `AIData/NEXT_DAY/strategy.json` 的 `env.above/total`（2026-11-04 实测 0/7 = 差环境；该文件为合法 UTF-8，读取须显式 UTF-8 解码，用 `Get-Content -Raw` 默认编码会乱码）
- 情绪 / 赚钱效应：用户原话或「无」
- 主线 / 题材：用户原话或「无」

> 四件套**有就写、没有写「无」，不替用户算**。候选数是环境信号，缺了注明。B+ 环境一天一次、T-1 收盘定（见 `journals/coach/PLAYBOOK.md` §2.12.1），**别与当日涨停家数/连板高度混为一谈**（两个「环境」不是一回事）。

### 3. 操作清单（逐笔，一行一笔）

| 代码 | 方向 | 买/卖价 | 仓位% | 止损价 | 盈亏% | 卖法(B+/旧/未标注) | 计划内? | 理由（用户原话一句） |
|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  | 计划内 / 计划外 |  |

- **`代码` 必填**（6 位 + `.SH/.SZ`）：小小A 要用 `AIData/1D` / `5M` 对账「用户说的买卖价 vs 当天实际高低点」，并验证止损是否真触发；**没记就写「无代码（不可对账）」，不许猜**。
- **卖法版本**：`B+` / `旧` / `未标注`（2026-11-04 用户决定全面改用 B+，见 `journals/coach/PLAYBOOK.md` §2.12）。用户没写就写「未标注」，**不按行为猜**；有把握时在备注写依据（如「14:55 持有 → B+」）。混用新旧卖法的日子**逐笔标**，周评才可归因。
- **止损价**可直接写「成本×0.95」（B+ 口径）。
- 其余格缺哪格写「无」；「止损价」= 用户设定的止损位，没设定写「无」。
- B+ 的「10:00 红盘宽度」数据源是 `AIData/INDEX_5M`（17 只宽基指数 5m，2026-01-05~2026-11-04），**不是 `AIData/5M`**。
- 理由**尽量逐字摘用户原话**，不做转述改写（小小A 明确说措辞比转述值钱）。

### 4. 盈亏

- 今日盈亏 ____% / 本月盈亏 ____%（用户写的数字；没有写「无」）
- 单笔最大盈利 / 亏损（代码 + %）
- 持仓与浮盈亏（若用户写了）

### 5. 纪律与错误

- 按计划止损：**是 / 否 / 无止损计划**
- 仓位是否超限：**是**（几成 → 上限几成）/ **否** / 无
- 计划外单：**有**（几笔）/ **无**
- 用户自述的错误：原文摘录
- **错误归类标签**（沿用 `TAGS.md`）：追高 / 硬开仓 / 未止损 / 仓位超限 / 风格漂移 / 无（可多选）

### 6. 风格标签

沿用 `TAGS.md` §1 / §3 的标签，多个用「/」分隔；无则「无」。

### 7. 值得回看的一句

用户**原文逐字**摘录（不改写）；可附 1-2 句备选，须标日期 / 行号出处。

### 8. 交接区（只给小小A，小志不下结论）

- **定义类开放问题**：如「长上影阈值多少算长」「追高和半路怎么分」——原文摘录 + 出处（日期 / 原文行号）。
- **边界单「可买可不买」**：最终**做没做** + 用户给的理由。
- 需要小小A 主张口径 / 评分的地方。

> 定义与口径由小小A 主张，小志只搬运事实，不替用户下结论。口径表见 `journals/coach/PLAYBOOK.md` §4.3「口径主张 v1」（小小A 维护，小志只引用、不改）。

### 9. 数据来源与缺口

- 日志路径：`journals/YYYY-MM-DD.md`（是否补写 / 更新）
- **缺失项清单**：如「未记仓位、未记止损价、未写候选数」——直接列，便于小小A 判断评分可信度。
- **下单时名单可用性（固定字段，必填）**：`可用` / `不可用` / `无名单`；后两者写时间戳证据（如「preclose 14:45:44 启动、15:57:28 完成；官方 21:52 生成 → 14:45–14:55 无名单」）。用于判定「按计划买」是否可归因名单，**避免把工具延迟算成用户「计划外/抢跑」**。
- **可用性默认（自 2026-11-09 起）**：`preclose_strategy.py` 已修复（14:40 触发 / 14:45 前就绪，实测 2~4s），该字段**默认「可用」**；只有再超时/未生成才写「不可用」+ 时间戳证据。
- **两版名单差异（自 2026-11-09 起尽量记）**：14:45 preclose 与 15:50 官方名单的**数量 / 首推 / 重叠差异**（数据源 `AIData/NEXT_DAY/preclose_strategy.json`、`strategy.json`；看 `generatedAt` 判断版本），用于评估「提前 5 分钟买」的代价。
- **对账数据源速查**：个股日线 `AIData/1D`；个股 5m `AIData/5M`；指数 5m `AIData/INDEX_5M`（B+ 宽度用，17 只宽基）；环境/次日策略 `AIData/NEXT_DAY/strategy.json`（`env.above/total`）；候选行数 `AIData/STRATEGY/TPO_M5`。
- **卖法版本**：见 §3；混用日逐笔标，周评归因用。

## 摘要长度

- 写进 `summaries/<日期>.md` 的可以完整展开；
- 发给小小A 的 `send_message` 摘要 ≤15 行：先给 §2/§3/§4/§5 的关键数，再给 §7 一句 + §8 交接项；没有的写「无」。
